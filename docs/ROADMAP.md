# 后续界面和功能概览

写于 2026-11-28，基于 `main` @ `a9fb2b5`（版本 1.3.0）。

这份文档给接手的 Agent 和人看：用户想做什么、每项能不能做、从哪个文件下手、哪些事没有验证。
项目规则在 [`AGENTS.md`](../AGENTS.md)，改代码前先读它。来龙去脉在 [`HANDOFF.md`](HANDOFF.md)。

本文件里的结论来自读代码和内置数据，没有在国服游戏里实测。没验证的事集中列在第 10 节。

## 1. 一览

| 编号 | 功能 | 结论 | 卡在哪 |
|---|---|---|---|
| A | 苹果风界面重构 | 能做 | 毛玻璃和苹果字体在 Windows 上受限 |
| B | 商店界面框选推荐装备 | 能做 | 要新做商店识别；购买顺序只有前三件有数据 |
| C | 按敌方阵容优化出装 | 部分能做 | 没有统计数据，只能写规则 |
| D | 按海克斯优化出装 | 暂时不能 | 数据只覆盖命运之武器一个海克斯 |
| E1 | 选人时识别队友 ID | 能做 | 要一张带聊天框的选人截图来定坐标 |
| E2 | 查队友战绩并评级 | 现有原则下不能 | 没有不连客户端的国服战绩来源 |

所有项目目前都没有开始写代码。

## 2. 不变的约束

这些来自 `AGENTS.md`，做下面任何一项都要守住：

- **不碰游戏客户端**（第 16 条）：不连 LCU、不走 2999 端口、不读内存、不注入、不模拟按键。只截屏识别和显示。
- **不加广告、不做商用功能**（第 18 条）：界面上保留数据署名
  `海克斯大乱斗统计数据（github.com/czgreat/aramhex-data），CC BY-NC 4.0`。
- **不直接改 main**（第 3 条）：开分支，推送，再合并。
- **测试基线**：`QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q`，期望 `1254 passed, 24 skipped`。

另外加一条本文件的约定：**凡是规则算出来的推荐，界面上要写明它是规则，不是统计结论。**
现有推荐全部来自对局统计，混在一起会误导用户。

## 3. A：苹果风界面重构

### 3.1 现状

| 文件 | 行数 | 内容 | 依赖它的测试文件 |
|---|---|---|---|
| `lolhex/ui/theme.py` | 159 | 配色常量、字体、QSS、调色板。强制浅色 | 2 |
| `lolhex/ui/mainwindow.py` | 1400 | 主窗口、托盘。混有更新、云控、查分、日志上传逻辑 | 16 |
| `lolhex/ui/overlay.py` | 1449 | 游戏内浮窗，全部用代码绘制，不走样式表 | 27 |

`theme.py` 的样式只作用于 `QMainWindow#main` 和 `QDialog`，不影响浮窗。
主窗口是单页竖排卡片：顶部状态、英雄卡片、标签页（出装、加点、设置）。

### 3.2 能做到和做不到

继续用 PySide6 Widgets 加 QSS，能做出圆角卡片、大留白、分段控件、深浅色。受限的两处：

- **毛玻璃**：要调 Windows 系统接口，Win10 和 Win11 效果不同，要单独适配。
- **字体**：苹果的 SF 字体不能随 Windows 软件分发。用微软雅黑，或随包带思源黑体这类开源字体。

### 3.3 分三步做

**第一步：只改 `theme.py`。** 配色、圆角、间距、字号都在这里，测试基本不用动。现值和建议起点：

| 常量 | 现值 | 浅色建议 | 深色建议 |
|---|---|---|---|
| `BG` | `#f2f4f8` | `#F2F2F7` | `#000000` |
| `CARD` | `#ffffff` | `#FFFFFF` | `#1C1C1E` |
| `LINE` | `#e1e6ee` | `#E5E5EA` | `#38383A` |
| `TEXT` | `#1d2433` | `#000000` | `#FFFFFF` |
| `MUTED` | `#667085` | `#8E8E93` | `#8E8E93` |
| `ACCENT` | `#2f6bd8` | `#007AFF` | `#0A84FF` |
| `GOOD` | `#1f8f50` | `#34C759` | `#30D158` |
| `BAD` | `#cf4436` | `#FF3B30` | `#FF453A` |

建议值取自苹果系统色，用户还没有确认。卡片圆角现在是 10px，按钮和输入框是 6px，
可以提到 12 到 14px 和 8px。QSS 里还有一些写死的颜色（`#fff7df`、`#f7f9fc`、`#e8ecf3` 等），
要一起收进常量，否则深色下会露出浅色块。

做深色要同时改 `palette()` 和"强制浅色"的逻辑，并决定是跟随系统还是手动切换。

**第二步：重排主窗口布局。** 先把更新（`UpdateWorker`）、查分（`RankWorker`）、云控提示
从 `MainWindow` 里拆出去，再动布局。不拆的话，改布局会牵动 16 个测试文件里的大部分。
源码版没有官方模块，查分、云控、自动更新本来就不工作（见 `lolhex/official.py`），
拆的时候可以考虑把这些入口在界面上隐藏。

**第三步：浮窗。** `overlay.py` 的 `BadgeLayer`、`ChampSelectLayer`、`ControlPanel` 都是
`paintEvent` 里直接画的，要改绘制代码。`AGENTS.md` 待办里提到的 1px 截断也在这里，顺便修。

### 3.4 等用户定

- 要不要深色模式，跟随系统还是手动切换。
- 要不要毛玻璃。
- 字体用微软雅黑还是随包带开源字体。

## 4. B：商店界面框选推荐装备

### 4.1 想要的效果

现在的出装建议画在三选一卡片上（`overlay.py` 的 `BadgeLayer._paint_item_hint`）。
用户想改成和选人界面一样：打开商店时，在装备图标上直接画框，框里写选取率和推荐顺序。

### 4.2 原理

和 `lolhex/vision/champselect.py` 相同：截屏，按窗口比例找到图标位置，比对图标，在透明浮窗上画框。
只截屏和显示，不违反第 16 条。

### 4.3 已有的和要新做的

| 已有 | 位置 |
|---|---|
| 图标比对 `IconBank` | `lolhex/vision/portraits.py`（现在只装英雄头像） |
| 装备图标的下载和本地缓存 | `lolhex/data/icons.py`、`lolhex/data/item_icons.json` |
| 197 件装备的名称、图标地址、属性标签 | `lolhex/data/bundled/item_metadata.json` |
| 按比例定位和静止画面缓存 | `champselect.py` 的 `_r(...)`、`Memo` |
| 浮窗分层绘制 | `overlay.py` 的 `_Layer`、`ChampSelectLayer` |

要新做：

- 判断商店是否打开（游戏内，`phase == "ingame"`）。
- 定位装备格子。商店的大小和位置是否固定没有实测。不固定就要先找商店边框，再推算格子。
- 给装备图标建一个 `IconBank`。商店里的图标比头像小，比对阈值要重新调。
- 适配不同分辨率和游戏内界面缩放。
- 在 `overlay.py` 加一层绘制（比如 `ShopLayer`），在 `engine.py` 的 `snapshot()` 里加对应字段。

两处注释提到商店文字会干扰海克斯识别：`lolhex/config.py:141`、`lolhex/vision/matcher.py:59`。
加商店识别时要确认两边不会互相误判。

### 4.4 数据能支持什么

| 要显示的 | 有没有数据 | 来源 |
|---|---|---|
| 单件装备胜率 | 有 | `hero_items.json`、`hero_item_holdings.json` |
| 单件装备选取率 | 能算 | 持有局数（`hero_item_holdings.json`）除以英雄总局数（`equipment_heroes.json`） |
| 前三件的顺序 | 有 | `core_builds.json`，`ordered: true`，每英雄最多三套，自带 `pick` 和 `win` |
| 第四件以后的顺序 | 没有 | [`AUGMENT-ITEMS.md`](AUGMENT-ITEMS.md) 写明结算装备不能证明购买顺序 |

所以框里前三件可以标"第 1、2、3 件"，其余只显示选取率和胜率。
现有代码有没有现成的"单件选取率"没有确认，先看 `lolhex/data/public.py` 和 `lolhex/panel.py`。
样本少的装备带 `low_sample: true`（阈值 3000 局），显示时要区分。

### 4.5 开工前需要

商店打开时的游戏截图，至少覆盖 1920×1080 和另一个常用分辨率，以及不同的界面缩放设置。
仓库里没有任何游戏截图，测试用的是 `tests/synth.py` 合成的画面。

## 5. C：按敌方阵容优化出装

### 5.1 识别敌方

- **敌方英雄**：能做。加载界面显示双方十个英雄，停留时间长，用头像比对或文字识别。
  代码里现在没有加载界面、计分板、敌方阵容的任何识别，要新写。
- **敌方出装**：只能在玩家按 Tab 时从计分板读。图标很小，识别不稳。建议放到最后。

### 5.2 推荐依据

内置数据里没有"敌方阵容对应装备胜率"，也拿不到原始对局，所以做不了统计式推荐。只能写规则，材料有两样：

- 英雄定位：`lolhex/data/static_bundled.json` 的 `heroes[*].roles`，例如 `["mage", "support"]`。
- 装备属性标签：`item_metadata.json` 的 `types`，例如 `Armor`（25 件）、`SpellBlock`（22 件）、
  `MagicResist`（5 件）、`ArmorPenetration`（20 件）、`MagicPenetration`（8 件）。

一种可行的规则：统计敌方五人的定位，法师多时，把该英雄常出装备里带魔抗标签的排到前面。
只在该英雄本来就常出的装备里调整顺序，不推荐它几乎不出的装备。

定位只有粗分类，同一个英雄走物理还是法术出装看不出来。规则的准确度有限，按第 2 节的约定在界面上写明。

## 6. D：按海克斯优化出装

`hero_augment_items.json` 的结构是"英雄 ID → 海克斯 ID → 配置"，支持任意海克斯。
但内置数据里 173 个英雄都只有命运之武器（3081）一项。客户端不重排，筛选和顺序由数据源决定，
详见 [`AUGMENT-ITEMS.md`](AUGMENT-ITEMS.md)。

出路有三条，按省事程度排：

1. 请上游数据仓库 [aramhex-data](https://github.com/czgreat/aramhex-data) 扩展覆盖的海克斯。客户端不用改。
2. 手写少量规则，例如拿到某类海克斯后优先某类属性的装备。同样要标明是规则。
3. 自己采集对局数据。国服没有公开的对局接口，这条路目前走不通。

在数据到位之前，这一项不建议开工。

## 7. E：选人时识别队友 ID 和查战绩

这一项分成两步，结论不同。

### 7.1 E1 识别队友 ID：能做

用户提出的做法：从选人界面左下角的聊天框里读队友的 ID。进场时系统消息每个队友一行。
只截屏，不违反第 16 条。

- 聊天框按窗口比例定位，用 `lolhex/vision/ocr.py` 读文字。现有代码没有处理聊天框，要新写。
- 现在 `champselect.py` 的 `NAME_BOXES` 读的是左侧每行的英雄称号，不是召唤师名字，不能直接复用。
- 进场消息会被聊天内容顶走，要在刚进选人界面时读并缓存。
- 召唤师名字没有字典可以纠错。英雄名能模糊匹配到 173 个英雄，名字错一个字就对不上。
  特殊符号、生僻字、`l/I/1`、`0/O` 容易错。可以读多帧取多数来减少错误。

两点没有确认：聊天框里显不显示 `#` 后面的编号（不显示的话重名玩家无法区分）；聊天框的准确坐标。
一张带聊天框的选人界面截图（最好 1920×1080）可以同时回答这两点。

### 7.2 E2 查战绩并评级：现有原则下不能

| 途径 | 能否查到 | 问题 |
|---|---|---|
| 连 LCU 或用客户端令牌 | 能 | 违反第 16 条。国服封号风险没有依据可以排除 |
| WeGame 的战绩接口 | 没验证 | 非公开接口，要用用户自己的 WeGame 登录态。能否按名字搜、有没有海克斯大乱斗的对局都没验证 |
| 自建战绩库 | 能 | 没有国服对局来源。原项目的查分走原作者的私有服务器，源码里不带（`lolhex/official.py`） |
| 只识别不查 | 不查 | 把队友 ID 列在浮窗里，可一键复制，用户自己去掌盟或 WeGame 查 |

Riot 公开接口不覆盖国服，并且对海克斯大乱斗的对局返回 403。搜到的国服同类工具
（例如 [lol-helper](https://gitee.com/nailaokekeye/lol-helper)）写明是调用 LCU 接口。

**建议**：先做"只识别不查"。成本低，完全合规，还能测出 OCR 读名字的准确率。
准确率和编号问题确认后，再由用户决定要不要接 WeGame，或者为这一项放开第 16 条。

"好队友还是坑货"的评级规则（看哪几局、用什么指标）也还没有定，要等有了数据来源再谈。

## 8. 建议顺序

1. A 第一步：只改 `theme.py`。
2. E1 的"只识别不查"版本，或 B 商店框选。两者互不依赖，哪个先拿到截图先做哪个。
3. C：加载界面识别敌方英雄，加规则式出装调整。可以复用 B 的显示层。
4. A 第二、三步：主窗口布局和浮窗。放在功能之后，是因为 B、C、E1 都要往浮窗加东西，先加完再统一改样式。
5. D：等数据。
6. E2：等用户决定。

`HANDOFF.md` 第 5 节的旧清单（改名换图标、许可证、数据镜像、更新提示、正式版 `release.yml`）仍然有效，
公开发布前必须做完改名和换 AppId。

## 9. 等用户决定和提供

决定：

- E2 查队友战绩：放弃，只做识别；还是接 WeGame；还是为它放开第 16 条。
- A 界面：深色模式、毛玻璃、字体（见 3.4）。
- C、D：是否接受规则式推荐，以及界面上怎么标注。

提供：

- 选人界面截图，带左下角聊天框（E1）。
- 商店打开时的游戏截图，多个分辨率和界面缩放（B）。
- 加载界面截图（C）。

截图里有其他玩家的名字。放进仓库当测试素材前要打码，或者只在本地用、不提交。

## 10. 没有验证的事

- 选人界面聊天框是否显示 `#` 后面的编号。
- 商店窗口的大小和位置是否固定，是否随界面缩放变化。
- 商店里的小图标用 `IconBank` 比对的准确率。
- 加载界面的头像位置在不同分辨率下是否按比例变化。
- WeGame 战绩接口现在能否使用、要什么凭证、是否包含海克斯大乱斗。
- 国服连接 LCU 的封号风险。腾讯安全中心定期公示处罚名单，但没有查到它对这类工具的明确说法。
- 现有代码里是否已经算好单件装备的选取率。
- 毛玻璃在 Win10 和 Win11 上的实际效果，以及和透明置顶浮窗是否冲突。
- 上游 aramhex-data 是否计划扩展 `hero_augment_items.json` 覆盖的海克斯。
